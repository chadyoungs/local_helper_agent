# Local Helper Agent
## Overview
Local Helper Agent is a local‑running AI agent system built on Ollama + FastAPI.
It adopts JSON‑based tool‑calling workflow with a dedicated **harness sandbox layer**, supports file upload, image processing, PDF processing, multi‑turn conversation with persistent sessions.

The harness layer enforces filesystem sandbox rules: LLM outputs only logical dirnames; the agent automatically maps them to real paths under `workspace/`. Absolute system paths and path‑traversal patterns are blocked.

## Project Structure
demo_agent/
├── config.py                   # Path settings, tool registry, system prompt template   
├── agent_core.py               # Agent core logic: session IO, harness sandbox, tool runner, prompt builder  
├── backend.py                  # FastAPI HTTP & NDJSON API entry point  
├── index.html                  # Front‑end chat UI (pure HTML/JS, no build step)  
├── sessions/                   # Persisted chat sessions (auto‑generated JSON files with metadata)  
├── workspace/  
│   ├── input/                  # Uploaded PDF / image files (harness input root)  
│   └── output/                 # Output files generated by tools (harness output root)  
|── tools/  
|   ├── pdf_merge.py            # Merge multiple PDF files  
|   ├── pdf2img.py              # Convert PDF pages to JPEG (supports password‑encrypted PDF)  
|   └── id_photo_bg_change.py   # Change background color of image  

## Requirements
- Python 3.10+
- Ollama installed and running locally

## Quick Start
1. Pull LLM model for Ollama
2. Start local Ollama service in background.
```
ollama pull qwen2.5:7b‑instruct
```
* Modify model name inside `backend.py` if you want to use another model.
3. Install dependencies:
```
pip install -r requirements.txt
```
* need to download .onnx file from Github while using rembg package
4. Launch FastAPI backend:
```
python3 backend.py
```
* Backend runs on `http://127.0.0.1:5001`
5. Open `index.html` directly in web browser.

## Front‑end Features

- 📎 File upload: upload PDF / image files into `workspace/input`
- 💬 Multi‑turn chat conversation
- 🔄 NDJSON streaming token output
- 📑 Sidebar session manager: create, switch, rename, delete chat sessions
- 💾 Session persistence: chat history saved to disk under `sessions/` with `created_at`, `updated_at` and `title` metadata
- 🔧 Formatted tool‑call panel: display tool name, arguments, stdout, stderr and return code
- 🔐 Auto prompt for password when handling password‑protected PDF

## Built‑in Tools

### pdf_merge

Merge multiple PDF files into one single PDF file.
Input: logical filenames located in `workspace/input`
Output: merged PDF saved to `workspace/output`

### pdf2img

Convert PDF pages to JPEG images.
- Support password‑encrypted PDF.
- Agent will ask user for password if missing.
- Use placeholder `__NO_PWD__` for documents without password.

### id_photo_bg_change

Change id photo background color with hex color code.
- Support custom hex color, e.g. `#FFFFFF` for white, `#FF0000` for red, `#0000FF` for blue.
- Input: image file from `workspace/input`.
- Output: processed image saved to `workspace/output`.

## Harness Sandbox Behavior

- LLM tool arguments use **logical filenames only**, do NOT output absolute filesystem paths.
- Bare input filename e.g. `2016.pdf` → automatically resolved to `workspace/input/2016.pdf`.
- Output logical folder name e.g. `2016_result` → automatically resolved to `workspace/output/2016_result`.
- Absolute paths and `../../` path traversal patterns trigger sandbox error and block tool execution.
- Missing input files return clean sandbox error, no raw Python traceback exposed to LLM or frontend.
- All intermediate harness debug information outputs to backend logger console / log file, not to user chat.

## Add New Custom Tools

1. Write standalone Python script under `tools/` directory.
2. Append new tool item to `TOOL_REGISTRY` inside `config.py`.
   - Fill `name`, `description`, `script_path` and `parameters`.
3. If new tool reads/writes files, extend `_rewrite_tool_arguments()` inside `agent_core.py` to apply harness path mapping.
4. Restart `backend.py`.

* Tools are executed via subprocess, isolated from main agent process.

## API Endpoints

| Endpoint | Method | Description |
| --- | --- | --- |
| `/sessions` | GET | List all sessions with metadata, sorted by `updated_at` descending |
| `/new_session` | POST | Create new chat session |
| `/session/{session_id}` | GET | Load full session container including metadata and message history |
| `/session/{session_id}` | DELETE | Delete session file from disk |
| `/chat` | POST | NDJSON streaming chat endpoint |

## Logging
- Log levels: `DEBUG`(path resolution, subprocess command), `INFO`(session create/save, tool invoke), `WARNING`(sandbox violation, tool failure), `ERROR`.
- Debug logs are only visible on backend side; never sent to frontend.
